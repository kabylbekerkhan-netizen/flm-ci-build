# Техническая спецификация: Разработка и инъекция мульти-инструментов в FL Studio Mobile (iOS)

## 0. ЖЕСТКИЕ ПРАВИЛА ОПТИМИЗАЦИИ КОНТЕКСТА И ТОКЕНОВ (ЧИТАТЬ ПЕРВЫМ)
Ты работаешь в среде **Windows** с большим бинарным архивом `target.ipa` (~300 МБ). Чтобы не переполнить контекстное окно и не тратить токены впустую, строго соблюдай следующие ограничения:

1. **ЗАПРЕТ НА ПРЯМОЕ ЧТЕНИЕ БИНАРНИКОВ:** Никогда не используй встроенные инструменты чтения файлов IDE (`read_file`, `view_file` и аналоги) на файлах `.ipa`, `.dwp`, `.instr`, `.wav` или исполняемом файле `FL Studio Mobile`.
2. **ЗАПРЕТ НА ПОЛНУЮ РАСПАКОВКУ:** Не распаковывай весь `target.ipa` на диск. Читай и извлекай только единичные файлы точечно через стандартный модуль Python `zipfile` в папку `workspace/`.
3. **ТОЛЬКО ЧИСТЫЙ PYTHON (БЕЗ MACOS CLI И ТЯЖЕЛЫХ ЗАВИСИМОСТЕЙ):** Среда выполнения — Windows. Не вызывай `otool`, `nm`, `plutil`, `codesign`, `unzip`. Для парсинга `Info.plist` используй встроенный модуль Python `plistlib`, для разбора бинарных заголовков (`Mach-O`, `.dwp`, `.instr`, `.wav`) — встроенный модуль `struct`. Не устанавливай сторонние библиотеки через `pip`, если задачу можно решить стандартной библиотекой Python.
4. **ЛИМИТ ВЫВОДА В ТЕРМИНАЛ (`stdout`):** Любой твой Python-скрипт должен выводить в консоль **не более 45 строк** за один запуск. Все подробные дампы сохраняй в `workspace/recon_state.json`.
5. **ПОШАГОВОЕ ВЫПОЛНЕНИЕ:** Выполняй ровно ту Фазу, которую запросил пользователь. После завершения Фазы остановись и жди команды.

## ФАЗА 1: Бесконтактная разведка `.ipa` и форматов инструментов

**Задача:** Написать и выполнить единый скрипт `scripts/phase1_recon.py`, который без распаковки всего архива изучит `target.ipa` и сохранит точные технические данные в `workspace/recon_state.json`.

**Что должен сделать скрипт `scripts/phase1_recon.py`:**
1. Открыть `target.ipa` через `zipfile.ZipFile`.
2. Найти `Info.plist` внутри `Payload/*.app/`, распарсить его через `plistlib.loads()` и извлечь:
   - `CFBundleIdentifier`, `CFBundleExecutable`, `CFBundleShortVersionString`.
   - Наличие ключей `AudioComponents` и `UIBackgroundModes` (поддержка Inter-App Audio).
3. Просканировать список путей внутри `.ipa` и составить карту ресурсов приложения:
   - Найти точные пути к заводским папкам с инструментами, сэмплами и пресетами (`.dwp`, `.instr`, `.flmpst`, `.wav`).
   - Подсчитать количество файлов каждого типа и вывести 5 самых маленьких файлов `.dwp` и `.instr`.
4. Извлечь в `workspace/samples_ref/` по 1 самому маленькому файлу `.dwp` и `.instr` (и связанные с ним сэмплы, если они лежат рядом).
5. Проанализировать структуру извлеченного `.dwp` / `.instr`:
   - Определить, является ли он контейнером (ZIP/RIFF/Custom Binary или JSON/XML) или монолитным бинарником с сэмплами внутри.
   - Сделать hex/ascii дамп заголовка и структуры зон клавиш (Keyzones: Root Note, Low Key, High Key, Velocity, Sample Path/Offset).
6. Проверить заголовок главного исполняемого файла `Payload/*.app/<CFBundleExecutable>` (прочитать только первые 4096 байт и список `LC_LOAD_DYLIB` через `struct` из потока `zipfile`), чтобы определить:
   - Зашифрован ли бинарник (`cryptid == 0` в `LC_ENCRYPTION_INFO_64`).
   - Список слинкованных системных фреймворков.
7. Записать результаты в `workspace/recon_state.json` и вывести в консоль краткую сводку (до 40 строк).

## ФАЗА 2: Разработка генератора и компилятора мульти-инструментов

*Выполняется только после успешного завершения Фазы 1 и подтверждения от пользователя.*

**Задача:** На основе точной структуры `.dwp` / `.instr`, полученной в Фазе 1, создать CLI-инструмент `scripts/build_instruments.py` без сторонних зависимостей.

**Функционал `scripts/build_instruments.py`:**
1. **Синтез эталонных сэмплов (если папка `input_samples/` пуста):**
   - Сгенерировать математически через `wave` и `struct` 3 готовых мультисэмплерных набора (по 12 нот в каждом, от C2 до C6):
     - `Custom_Dark_Pluck` (моделирование щипка акустической струны по алгоритму Карплуса-Стронга с мягким лоу-пасс фильтром).
     - `Custom_Sub_808` (насыщенный саб-бас с питч-огибающей на атаке и легким нечетным дисторшном).
     - `Custom_LoFi_Keys` (FM-электропиано с легкой детонацией и спадом высоких частот).
2. **Парсинг пользовательских сэмплов (если в `input_samples/` есть папки с `.wav`):**
   - Автоматически определять корневую ноту (Root Note) из имени файла (например, `C3`, `F#4` или номер ноты) либо по базовой частоте (Zero-Crossing / Autocorrelation), и автоматически распределять зоны клавиш (`LowKey` – `HighKey`) без пробелов по всей клавиатуре (0–127).
3. **Сборка нативных банков FL Studio Mobile:**
   - Упаковать каждый инструмент в точный формат `.dwp` / `.instr`, полностью совместимый с движком DirectWave в FL Studio Mobile (строго по байтовой спецификации из Фазы 1).
   - Сохранить готовые файлы инструментов в папку `dist/instruments/`.

## ФАЗА 3: Инъекция в `.ipa` и сборка под SideStore

*Выполняется по команде пользователя.*

**Задача:** Написать скрипт `scripts/inject_ipa.py`, который:
1. Создает два варианта доставки инструментов:
   - **Вариант А (Прямой пакет для папки `My Instruments`):** Готовый архив/папка в `dist/direct_import/`, которую можно просто скопировать в приложение «Файлы» -> `FL Studio Mobile` -> `My Instruments` без переустановки `.ipa`.
   - **Вариант Б (Модифицированный `.ipa` для SideStore):** Потоково копирует `target.ipa` в `dist/FLM_Custom.ipa`, добавляя сгенерированные инструменты напрямую во внутренний заводской банк `Payload/*.app/...` с сохранением корректных прав доступа UNIX (`external_attr`) в ZIP-заголовках, чтобы SideStore корректно подписал приложение.
2. Проверяет целостность архива `dist/FLM_Custom.ipa` и выводит финальный отчет.
